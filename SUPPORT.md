# Support

## How to get help

| If you… | Then… |
| --- | --- |
| Found a bug or a release misbehaves | Open a [bug report](https://github.com/danielvm-git/big-release/issues/new?template=bug_report.yml) |
| Have a question about how to configure or use big-release | Open a [GitHub Discussion](https://github.com/danielvm-git/big-release/discussions) |
| Want to request a new publisher, language, or feature | Open a [feature request](https://github.com/danielvm-git/big-release/issues/new?template=feature_request.yml) |
| Are migrating from semantic-release and something differs | Open a [Discussion](https://github.com/danielvm-git/big-release/discussions) with your before/after |
| Found a security vulnerability | Follow [`SECURITY.md`](./SECURITY.md) — **do not** open a public issue |

## Before asking

Please check these first — it usually answers the question:

1. **[`README.md`](./README.md)** — what big-release is, how to install and use it.
2. **[`docs/`](./docs)** — the documentation (tutorials, how-to, reference, explanation).
3. **[`.big-release.yml` example](./README.md#configuration)** — the configuration reference.
4. **Existing [issues](https://github.com/danielvm-git/big-release/issues)** and
   [discussions](https://github.com/danielvm-git/big-release/discussions)** — your
   question may already be answered.

## Response expectations

This project is maintained on a best-effort basis. Issues and discussions are
reviewed regularly but do not carry an SLA. PRs that fix a real defect or add
a publisher tend to move fastest.

## Commercial support

None available. This is an open-source tool, not a product.
