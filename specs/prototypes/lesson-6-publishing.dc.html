Publishing

big-release publishes to multiple registries. This lesson covers setting up each publisher.

npm

Setup

# 1. Create npm token
# Go to https://www.npmjs.com/settings/tokens
# Create a "Publish" token

# 2. Set environment variable
export NPM_TOKEN="your-npm-token"

# 3. Configure .big-release.yml
publishers:
  npm:
    enabled: true

# 4. Ensure package.json has publishConfig
{
  "publishConfig": {
    "access": "public"
  }
}

Scoped packages

For scoped packages (@scope/package), set access to public:

{
  "name": "@danielvm-git/my-package",
  "publishConfig": {
    "access": "public"
  }
}

PyPI

Setup

# 1. Create PyPI token
# Go to https://pypi.org/manage/account/token/

# 2. Set environment variable
export PYPI_TOKEN="your-pypi-token"

# 3. Configure .big-release.yml
publishers:
  pypi:
    enabled: true

# 4. Ensure pyproject.toml has build system
[build-system]
requires = ["setuptools", "wheel"]
build-backend = "setuptools.backends._legacy:_Backend"

crates.io

Setup

# 1. Create crates.io token
# Go to https://crates.io/settings/tokens

# 2. Set environment variable
export CRATES_TOKEN="your-crates-token"

# 3. Configure .big-release.yml
publishers:
  crates:
    enabled: true

# 4. Ensure Cargo.toml has required fields
[package]
name = "my-crate"
version = "0.1.0"
description = "A short description"
license = "MIT"

Go Proxy

Setup

# 1. Configure .big-release.yml
publishers:
  goproxy:
    enabled: true

# 2. Ensure go.mod exists
module github.com/yourname/yourmodule

# 3. Tag-based publishing
# big-release creates a tag like v1.0.0
# Go Proxy automatically picks it up

Note: Go Proxy does not require a token. Publishing happens automatically when you push a SemVer tag to GitHub.

Dry-run mode

Always test before publishing:

# Dry run — calculates version without publishing
big-release --dry-run

# Output shows what would happen:
# - Version to be released
# - Changelog to be generated
# - Packages to be published

Multiple publishers

Enable multiple publishers in one configuration:

# .big-release.yml
publishers:
  npm:
    enabled: true
  pypi:
    enabled: true
  crates:
    enabled: false  # Not all projects need all registries

Verification

After publishing, verify the release:

# Check npm
npm view @danielvm-git/my-package version

# Check PyPI
pip index versions my-package

# Check crates.io
cargo search my-crate

# Check Go Proxy
go list -m -versions github.com/yourname/yourmodule
