Conventional Commits

Conventional Commits is a specification for commit messages that allows automated tools to determine the next version. Every commit message follows a simple format:

type(scope): description

[optional body]

[optional footer(s)]

Commit types

TypeDescriptionVersion bumpExample
featA new featureMINORfeat(auth): add login with Google
fixA bug fixPATCHfix(api): handle empty response
docsDocumentation changesNonedocs: update README
styleCode style changesNonestyle: format with prettier
refactorCode refactoringNonerefactor: extract auth module
perfPerformance improvementsPATCHperf: optimize database queries
testAdding testsNonetest: add auth unit tests
buildBuild system changesNonebuild: upgrade webpack
ciCI configurationNoneci: add GitHub Actions
choreMaintenance tasksNonechore: update dependencies
revertRevert a commitPATCHrevert: feat(auth): add login

Breaking changes

A breaking change triggers a MAJOR version bump. Mark it with ! after the type or a BREAKING CHANGE: footer:

# Option 1: ! suffix
feat(api)!: change response format

# Option 2: footer
feat(api): change response format

BREAKING CHANGE: response is now { data: [], meta: {} }

Scope

The scope is optional and provides context about the change. It should be the module, component, or feature affected:

feat(auth): add OAuth2 support
fix(payment): handle currency conversion
docs(readme): add installation guide

Remember: big-release reads these commit messages to calculate versions. The format is not just for humans — it is machine-readable. Follow it consistently for accurate versioning.
