Brownfield Migration

Adding big-release to an existing project requires handling existing tags and history. This lesson covers the migration process.

Before you start

Check your existing tags:

# List all tags
git tag --list

# Show latest version
git tag --list --sort=-v:refname | head -1

Important: big-release finds the latest tag matching your tagFormat and analyzes commits since that tag. Existing tags are compatible as long as they follow SemVer.

Step 1: Add big-release

# Install big-release
go install github.com/danielvm-git/big-release/cmd/big-release@latest

# Create configuration
cat > .big-release.yml << EOF
branches:
  - name: main
tagFormat: "v${version}"
plugins:
  - changelog
  - git
publishers:
  npm:
    enabled: true
EOF

Step 2: Verify tag detection

# Dry run — shows what version would be released
big-release --dry-run

# If it shows the wrong version, check your tagFormat
# matches your existing tags

Step 3: Handle existing changelog

If you have an existing CHANGELOG.md, big-release will append to it. If you want to start fresh:

# Backup existing changelog
mv CHANGELOG.md CHANGELOG.md.bak

# big-release will create a new one

Step 4: Migrate from semantic-release

If migrating from semantic-release:

# 1. Remove semantic-release config
rm .releaserc release.config.js

# 2. Remove semantic-release from devDependencies
npm uninstall semantic-release @semantic-release/*

# 3. Add big-release config
# (see Step 1 above)

# 4. Update scripts
# Remove: "release": "semantic-release"
# Add: "release": "big-release"

# 5. Test
big-release --dry-run

Step 5: Update CI/CD

Update your CI configuration to use big-release:

# GitHub Actions example
- name: Release
  env:
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
    NPM_TOKEN: ${{ secrets.NPM_TOKEN }}
  run: npx big-release
