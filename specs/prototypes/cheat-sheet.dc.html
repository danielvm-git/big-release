Cheat Sheet

Every command, config key, and environment variable from the course, in one place.

CLI commands

CommandWhat it does
big-releaseCalculates the next version, generates the changelog, and publishes
big-release --dry-runShows what would happen without publishing anything
big-release --verbosePrints structured JSON log lines for each step
git tag --listLists existing tags — check before a brownfield migration

JSON log format

Every --verbose run emits one structured JSON object per line:

{"level":"info","msg":"Analyzing commits..."}
{"level":"info","msg":"The next release version is 1.2.0"}
{"level":"info","msg":"Generating changelog..."}
{"level":"info","msg":"Publishing to npm..."}
{"level":"info","msg":"Released 1.2.0"}

.big-release.yml reference

branches:
  - name: main              # branch(es) that trigger a release
tagFormat: "v${version}"    # git tag format
initialVersion: "0.1.0"     # used only for the first release (default 1.0.0)
plugins:
  - changelog                # generates CHANGELOG.md
  - git                       # commits changelog + creates the tag
publishers:
  npm:      { enabled: true }
  pypi:     { enabled: true }
  crates:   { enabled: false }
  goproxy:  { enabled: false }
KeyDescription
branchesList of branches big-release runs on
tagFormatGit tag template, e.g. v${version}
initialVersionVersion used for the very first release (default 1.0.0)
pluginsSteps to run: changelog, git
publishers.*.enabledToggles npm, pypi, crates, or goproxy publishing

Environment variables

VariableRequired for
NPM_TOKENPublishing to npm
PYPI_TOKENPublishing to PyPI

GITHUB_TOKENCreating releases & pushing tags on GitHub

Deployment note

This course itself ships as a static site, published with GitHub Pages:

  • Served from the /docs folder on the default branch
  • All links between lessons are relative paths — no absolute URLs
  • Zero external runtime dependencies — no build step, no CDN JS required to read the lessons
